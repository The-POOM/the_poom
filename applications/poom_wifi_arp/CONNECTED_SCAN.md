# Connected SCAN NET discovery

The existing **BEAST → SCAN NET** now offers ARP Discovery and Ping Discovery. Both use the existing saved Wi-Fi connection flow. Ping sends ICMP echo requests over the connected STA interface, retains responding IPv4 addresses and measured round-trip time, and resolves a MAC only when the ARP cache supplies one. It honors smaller subnets, including /31 and /32; networks larger than /24 are limited to the device's local /24 slice, shown as **Local /24 only**. Silence does not establish that a host is absent: ICMP can be filtered.

Select a discovered host with A for the existing common TCP/UDP/SSH service probe, or RIGHT for **FULL TCP SCAN**. The latter shows the selected IP and ports 1–65535 before A starts it. B stops the scan; the result retains any open ports found before cancellation. UP/DOWN pages through open ports. A full connect scan can take minutes, particularly when packets are silently discarded. It uses up to eight concurrent nonblocking sockets with 250 ms connect deadlines and 25 ms select polls. Immediate refusals complete sooner. Socket exhaustion drains existing probes before retrying and never reports an unattempted port as closed. Every open port fits in the 8 KiB bitmap, including port 65535.

**Find Port** offers CUSTOM PORT plus Telnet TCP 23, SMTP TCP 25, DNS TCP 53, HTTP TCP 80, HTTPS TCP 443 and RDP TCP 3389. Presets reuse the existing one-port-across-discovered-hosts flow. They identify reachable TCP ports; they do not establish which application actually serves them. The existing custom TCP/UDP/SSH controls remain available.

Ping uses one raw socket and at most sixteen outstanding requests. Replies must match the IPv4 source, ICMP echo-reply type/code, identifier, sequence, payload and checksum. Duplicate, malformed and unrelated packets cannot create additional hosts. The bounded host table holds up to 254 entries. Larger networks are not scanned beyond the stated local slice. IPv6 discovery, UDP full-range scans, service-version fingerprinting and routed-network expansion are outside this change.

Back/Exit requests cancellation and waits for workers to close sockets before freeing the host table or taking down Wi-Fi. ARP and common-service probes now cooperate with cancellation too. `menu_poom_wifi_arp_stop()` returns true only after session cleanup; a false result leaves ownership with SCAN NET and must block CLI takeover. No worker is forcibly deleted while it may own a socket. The existing UI status task is released only after worker cleanup.

`tests/host/run_net_scan_tests.ps1 -Compiler <host-gcc>` runs the production TCP/ICMP engine against fake socket functions; it opens no OS network socket. Coverage includes all 65535 TCP ports, the bitmap upper boundary, measured eight-way timeout batching, reduced socket capacity, allocation/fcntl/select/getsockopt errors, cancellation, disconnection, complete socket closure, subnet masks and ICMP source/payload/checksum/duplicate handling. Object compilation with the pinned ESP-IDF 6.1/C5 flags checks the menu and both backend sources. Full firmware linking and physical network acceptance are separate checks.

For lab acceptance, use an owned AP and host with a known allowed port and a refused port, compare ICMP replies to the displayed host list, stop during ping and full TCP scanning, reopen SCAN NET, and check CLI handoff. No live network discovery or port scan was run during implementation.
